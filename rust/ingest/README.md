# cine-rec-ingest — the ingest lane port (rust-port, waves C+D)

The ingest lane of cine-rec-engine in Rust. The Python package stays
the source of truth (rust-port plan); every ported piece is proven
against fixtures generated by running the REAL Python modules — never
by re-deriving expected values from the port itself.

## What landed

| Module | Ports | Contract |
|---|---|---|
| `rate` | `ingest/rate.py` | Pure `TokenBucket` (clock injected) + async `RateLimiter`. Waits/token levels bit-exact against a golden trace of the real Python limiter under a scripted clock. The lock is held ACROSS the sleep, like `asyncio.Lock` — concurrent acquirers queue, not herd. |
| `exports` | the pure core of `ingest/exports.py` | URL builders byte-compatible; strict `parse_export`; lenient `parse_line` (KeyError/ValueError → skip, TypeError → loud, CPython 3.12's exact per-type messages); `LineBuffer` with the FAITHFUL QUIRK that a final unterminated line is dropped by the streaming path; starter filters (NaN popularity never below the floor). |
| `loader` | `ingest/loader.py` (wave D) | Row builders, catalog upserts and bridge MIRRORING through the SINGLE registry (`cine_rec_db::SchemaMap`); stats byte-identical; the HTTP half is the `TitleFetcher` seam (wave E). See the parity model below. |
| `cli` | the argument surface of `ingest/cli.py` | Parser, validation order (dsn then key), defaults — unit-tested. Command bodies are wave E. |
| `pyval` | Python semantics | `int()`/`float()`/truthiness/`repr` over JSON values — where the PYTHON CODE converts (as opposed to asyncpg — see below). |
| `date` | the `datetime.date` slice | Hinnant civil dates; `%m_%d_%Y` with glibc's `%Y` (no zero-padding of small years). |

The wave-C private table registry was REMOVED when `cine_rec_db`'s
`SchemaMap` landed: one registry, owned by the db crate.
`tests/schema_map_bridge.rs` cross-checks SchemaMap against the
Python-generated `tables_cases.json` fixture (decisions, active maps,
rendered SQL). Error MESSAGE texts intentionally diverge (SchemaMap's
domain — see the queue note for session 1).

## The loader conversion rule (the whole design in one line)

A field is TYPED exactly where the PYTHON BUILDER converts it
(`int()`, `str(x or "")`, `_as_date`, `bool(...)`, the `.get()`
extractions) and stays a RAW JSON value where Python passes through —
those raw values fail at BIND time, where asyncpg's encoder fails
them. A string `popularity: "23.5"` therefore builds a row on both
sides and LANDS as numeric 23.5 (asyncpg decodes str→Decimal).

And the bind encoders are ASYNCPG's, not Python's (review M-1, every
branch verified live):

| Param | asyncpg accepts | asyncpg rejects |
|---|---|---|
| int4/int8 (+`bigint[]` elements) | int, float (truncated toward zero: 120.5→120, -0.7→0), bool (0/1) | **strings** (`int("120")` would succeed at a builder site — the bind must not) |
| numeric | int (exact), float as `Decimal(float)` — the EXACT decimal expansion of the double in MINIMAL form (`decimal_exact()` builds the BigDecimal from the f64 bits with the mantissa's trailing zero bits folded into the exponent: `Decimal(7.0)` is '7', never '7.000…0'; PG's own `float8::numeric` rounds differently) — bool (0/1), and strings via `Decimal(str)`: whitespace/underscores/exponents, ARBITRARY precision kept | unparseable strings, list/dict |

Two more Python-evaluation-order pins from the same reviews: the
bridge **DELETE runs before the row binds** (Python builds infallible
tuples at the call site; the asyncpg ENCODER fires inside
`executemany`, after the delete — so a huge `cast_order` or a
non-string `department` fails with the bridge already mirrored to
the new payload), and the keywords **fallback slot keeps a falsy
NON-iterable** (`results: null/0/false` — no `or []` behind
`.get("results", [])`: the dim is skipped and the `_sync_bridge` args
raise `TypeError`), while falsy ITERABLES (`""`/`{}`/`[]`) — there
and in `genres` — iterate empty and INGEST with the bridge mirrored
to empty.

## Parity model

```
tests/fixtures/gen_rate_trace.py        → rate_trace.json
tests/fixtures/gen_exports_fixtures.py  → exports_cases.json + exports_*.gz
tests/fixtures/gen_tables_cases.py      → tables_cases.json
tests/fixtures/gen_loader_parity.py     → loader_payloads.json + loader_parity_cases.json
tests/fixtures/gen_loader_live.py       → runs the REAL loader into a schema (live)
```

The loader is pinned at two levels:

* **Offline** (`tests/loader_parity.rs`) — the real PURE functions
  (row builders, keep_cast/keep_crew, rec rows, gate matrix incl.
  gate RAISES, completeness, error texts) over a 39-case corpus: a
  full movie touching every table, the shrink/mirror re-ingest,
  movie 155 + tv 155 together, the asyncpg-encoder cases, mid-batch
  failure shapes, INT4-busting cast order, float character repr,
  unhashable crew job, non-dict recommendations — plus the round-2
  families: round floats, cast/crew pre-then-failing-re-ingest
  pairs, keywords falsy-non-iterable results, genres as empty
  iterables. Regeneration is bit-identical.
* **Live** (`tests/loader_live.rs`, `CINE_REC_S3_DSN`) — the REAL
  `TmdbIngest` (fetch patched per case; the patch bypass is
  documented, and `fetch_none` steps exercise the fetch-error →
  failed path explicitly) writes schema `pyload`; the Rust loader
  replays the same 40-step plan into `rsload` (all 20 tables remapped
  through SchemaMap — the integrator path). Comparison: symmetric
  EXCEPT on every table (updated_at/synced_at excluded), numeric
  columns compared additionally AS `::text` (scale is part of the
  stored representation — see below), stats field-for-field, an
  explicit H-1 invariant assertion (movie 155 ingested AFTER tv 155
  must leave the series' networks in place — a bug both sides shared
  would pass EXCEPT and only this catches), and a must-be-non-empty
  list. Failure paths are part of the plan: both sides must reach
  the SAME partial state (e.g. a credited person without an id
  leaves the fact row committed and the people batch unwritten; a
  keyword missing its name fails AFTER people+genres — Python's
  evaluation order, replicated; a huge cast order / non-string
  department fails AFTER the bridge delete — the executemany
  encoder's point).

**H-1 (source bug, fixed on BOTH sides in one change):** the networks
bridge synced on EVERY medium, so ingesting a movie deleted the
networks of a series sharing its id (TMDB ids collide across media —
AGENTS.md invariant 4). `ingest/loader.py` and `loader.rs` both gate
the networks dim+sync on tv-only now, with the live assertion above
pinning it forever.

## Portability discoveries worth remembering

1. **asyncpg's numeric codec is `Decimal`, three ways** (all verified
   live): float → `Decimal(float)` = the exact binary expansion in
   MINIMAL form (7.9 → 7.9000000000000003552713678800500929355621337890625,
   7.0 → '7' — strip the mantissa's trailing zero bits, or every
   round double stores ~50 phantom zeros; PG's `float8::numeric`
   gives 7.9 — NOT the same); str → `Decimal(str)`
   with Python's acceptance rules; bool → 0/1. Int params truncate
   floats and REJECT strings; `bigint[]` encodes element-wise.
   And SQL `EXCEPT` compares numeric BY VALUE — `7 = 7.000…0` — so a
   scale divergence is invisible to it; compare `::text` too.
2. **The float black hole** (rate): a sub-ulp wait is absorbed by the
   clock (`t + d == t`) — the wrapper floors sleeps at 1ns to
   reproduce a real clock's self-healing under paused/virtual time.
3. **tokio timers tick at 1 ms** — pacing tests assert with ms
   tolerance; exact math lives in the bit-exact golden.
4. **glibc `%Y` does not zero-pad** small years (`date(9,1,5)` →
   `01_05_9`).
5. **CPython 3.12 subscript messages differ per type** (`not 'str'`
   vs `not str` vs `not subscriptable`) — pinned per case.
6. **Python's gzip over EMPTY input iterates to EOF without error**;
   flate2 reports a truncated header — special-cased.
7. **Strict vs streaming asymmetry**: whole-file `parse_export`
   INCLUDES a trailing unterminated line; the streaming loop DROPS it
   (no post-loop flush). Both pinned.
8. **`fromisoformat` raises the date-constructor's messages** for
   out-of-range components ("month must be in 1..12"), not
   "Invalid isoformat" — the component texts come from `crate::date`.

## Known divergences (documented, all pathological for TMDB input)

* **Numeric `NaN`/`Infinity` STRINGS**: asyncpg stores numeric NaN/∞
  (`Decimal('NaN')` binds; PG ≥ 14 numeric supports it) — BigDecimal
  cannot represent them and sqlx has no numeric-NaN encoding, so here
  the title FAILS LOUDLY instead. Pinned by a unit test.
* **`str(float)` exponent forms**: python `1e+16`/`1e-07` vs Rust
  `1e16`/`1e-7` (the common `.0` case matches: 5.0 → "5.0").
* **`date.fromisoformat` extra forms** (3.11+): compact/week dates
  (`20240105`, `2024-W01-1`) parse in Python, not here (dashed only).
* **Non-string `_as_date` input**: ValueError in Python (via `str()`)
  vs TypeError here — same outcome (title failed).
* **`str()` of a list/dict** in `str(x or "")` slots → `""` here
  (Python would render a repr).
* **Python-json NaN/Infinity LITERALS**; bignum ids beyond i64;
  non-ASCII decimal digits — as in wave C (see `pyval` docs).
* **genres as an iterable non-list** (string/dict): EMPTY ones
  (`""`/`{}`) iterate to nothing in Python and INGEST with the genre
  map mirrored to empty — replicated exactly (round-2 M-3′). A
  NON-empty one fails in Python at element access
  (`string indices must be integers`); here a not-iterable TypeError
  — same failure point, coarser message.

## Run

```bash
CARGO_BUILD_JOBS=2 cargo test -j2 --lib
for t in exports_parity rate_parity rate_async schema_map_bridge loader_parity; do
    CARGO_BUILD_JOBS=2 cargo test -j2 --test $t
done
# live (needs a Postgres and the repo venv):
CINE_REC_S3_DSN=postgres://... cargo test -j2 --test loader_live -- --test-threads=1
```

and run binaries sequentially.

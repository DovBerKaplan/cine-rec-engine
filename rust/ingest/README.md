# cine-rec-ingest — the ingest lane port (rust-port, wave C)

The DB-free core of `ingest/` (plus the pure mapping logic of
`cine_rec_engine/tables.py`), ported with the same rules as the
scoring crate: **the Python package is the source of truth**, and
parity is carried by fixtures generated by running the REAL Python
modules — never by re-deriving expected values from the port itself.

Wave C scope (this crate): everything that does not need db traits or
a runtime clock. Wave D/E will wire the IO edges on top.

## What landed

| Module | Ports | Contract |
|---|---|---|
| `rate` | `ingest/rate.py` | Pure `TokenBucket` (clock injected as f64 seconds) + async `RateLimiter` (tokio). Waits/token levels/return clocks bit-exact against a golden trace of the real Python limiter under a scripted clock. The async wrapper holds the lock ACROSS the sleep, like `asyncio.Lock` in the original — concurrent acquirers queue, not herd. |
| `exports` | the pure core of `ingest/exports.py` | URL builders byte-compatible; strict `parse_export` (multi-member gzip); lenient `parse_line` (KeyError/ValueError → skip, TypeError → loud, with CPython 3.12's exact per-type messages); `LineBuffer` (the streaming line splitter) with the FAITHFUL QUIRK that a final unterminated line is silently dropped; `entry_passes` starter filters (NaN popularity never compares below the floor → NaN entries pass). |
| `tables` | `cine_rec_engine/tables.py` | `LOGICAL_TABLES` registry, physical-name validation, file/env merge (env wins), `{t_<logical>}` resolution — pure functions, Python's exact error texts. |
| `pyval` | Python semantics | `int()`/`float()`/truthiness/`repr()` over JSON values — the phase-2 "truthiness is part of the contract" lesson applied to the export field expressions. |
| `date` | the `datetime.date` slice | Hinnant civil-date algorithms; `%m_%d_%Y` formatting with glibc's `%Y` (no zero-padding of small years). |

## Parity model

```
tests/fixtures/gen_rate_trace.py       → rate_trace.json
tests/fixtures/gen_exports_fixtures.py → exports_cases.json + exports_*.gz
tests/fixtures/gen_tables_cases.py     → tables_cases.json
```

Each generator RUNS the real Python implementation (the wt3 venv,
repo root) and freezes what it actually did:

* **rate** — the real `RateLimiter` with `time.monotonic` and
  `asyncio.sleep` monkeypatched: scripted clock advances, partial
  advances (multi-sleep acquires), a backwards clock, a NaN rate.
  Regeneration is bit-identical.
* **exports** — `_parse_line` on crafted raw lines; `parse_export`
  on whole corpora (happy, multi-member, no-trailing-newline,
  corruption families with error-class + message-parity flags); the
  URL matrix across calendar boundaries; and the REAL
  `iter_export_ids` driven end-to-end through a duck-typed mock
  session (no HTTP) over raw gz bytes in 13-byte chunks — pins the
  streaming semantics INCLUDING the dropped-tail quirk.
* **tables** — `set_table_map` / env+file load / `name` / `resolve`
  probes with exact error texts. io_edge cases (missing map file) are
  Python-only; the Rust API takes the already-parsed map value.

Regenerate only when the PYTHON behavior legitimately changes, and
regenerate + re-commit fixtures in the same change (fixtures and code
are one contract — same rule as the scoring goldens).

## Portability discoveries worth remembering

1. **The float black hole** (rate): a token deficit of one ulp yields
   a wait (~2e-17 s) smaller than the clock's own ulp; adding it to
   `t` is a no-op, so a clock that only ever advances by the
   requested wait never recovers and the acquire loop spins. Real
   clocks self-heal (wall time passes during the yield). The async
   wrapper quantizes every sleep to ≥ 1 ns, reproducing that dynamic
   under paused/virtual clocks too; the pure bucket stays untouched
   and the golden trace pins the sticky-token waits themselves.
2. **tokio timers tick at 1 ms** — the sub-ns recovery above lands on
   the next tick, so paced tests assert with ms tolerance; the exact
   math lives in the bit-exact golden, not in wall-clock assertions.
3. **glibc `%Y` does not zero-pad** small years (`date(9,1,5)` →
   `01_05_9`); `{:04}` would silently break byte-compat.
4. **CPython 3.12 subscript messages differ per type**: strings say
   `string indices must be integers, not 'str'`, lists say
   `list indices must be integers or slices, not str` (quotes DROPPED
   in 3.12), scalars say `'X' object is not subscriptable`. The
   fixture pins all three; a uniform message would have drifted.
5. **Python's gzip over EMPTY input iterates to EOF without error**
   (0 entries); flate2's decoder reports a truncated header —
   special-cased to match.
6. **Strict vs streaming asymmetry**: whole-file `parse_export`
   INCLUDES a trailing unterminated line (`for raw in f`), while the
   streaming `iter_export_ids` DROPS it (the loop only splits on
   `\n`, no final flush). Both behaviors are pinned; wave D must not
   "fix" the quirk.
7. **serde_json is strict JSON**: Python's json accepts `NaN` /
   `Infinity` literals and produces non-finite entries; here such
   lines fail at parse (skip in the lenient path, ValueError-class in
   the strict one). Also: bignum ids (Python `int(1e300)` succeeds)
   are a loud Value error — out of i64 by design. Both divergences
   are pinned by unit tests, not silently.

## Known divergences (documented, all pathological for TMDB input)

* NaN/Infinity JSON literals (see above).
* Integer ids outside i64 (Python builds bignums).
* Non-ASCII decimal digits in numeric strings (`int("٤٢")`).
* JSON-syntax error message TEXTS (classes match — JSONDecodeError is
  a ValueError; UnicodeDecodeError likewise).
* Multi-invalid table maps: Python reports the first offender in
  file/env iteration order; serde's map is sorted, so the file side
  iterates alphabetically. Single-offender maps are identical.

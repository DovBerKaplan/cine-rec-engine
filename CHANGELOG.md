## [0.10.0] — 2026-10-08

### Added — M3 (RFC §5): regression hardening
- **160-pair consensus judgments file** (was 10 hand pairs): stratified
  by genre × decade × medium, generated by `eval/build_judgments.py`
  from the bundled demo catalog. Inclusion = two-agreement consensus (a
  structured-metadata rule AND the embedding space must agree; goods
  are TMDB-graph-head or genre+keyword-overlap picks that are
  story-disjoint from the seed — the engine collapses collections and
  blocks the seed's own saga by design, so saga siblings are never a
  valid expectation). `--validate` scores the file per rule against a
  live DB before any gate is wired.
- **Raised eval gates, enforced in the harness itself**: `eval/eval.py
  --min-pairwise 0.75 --min-ndcg 0.28 --min-coverage 0.50` exits
  nonzero on failure; CI calls it directly (no output parsing). Engine
  measures 0.88 / 0.34 / 0.58 on the new file. The RFC's 0.40 NDCG
  target was pre-measurement — even a pure-cosine oracle cannot clear
  it on the 830-title pool; floor set measured-minus-margin (noted in
  the RFC). The coverage floor is the list-diversity non-drop guard.
- **Local integration harness**: `pytest -m integration` /
  `make test-integration` runs the CI demo-eval class of tests — recall
  smoke, the eval regression gate, personalization end-to-end (watched/
  disliked never resurface, vector channel active, second request is a
  cache hit), and the user-tilt contract — against a throwaway
  pgvector container (auto-spun) or `CINE_REC_INTEGRATION_DSN`. Skips
  cleanly offline; the offline suite stays the default loop.
- **`GET /metrics`** (Prometheus text): per-path latency histogram,
  cache hit rate, recall-channel coverage — plain in-process counters
  (`cine_rec_engine/metrics.py`), observed from the serve middleware,
  the cache get/set paths, and the channel-harvest loop.
- **The six reserved cinematic features are documented** (narrative/
  tone/arc/pacing/audience + heuristic_score): not covered by the
  published weights.json by design — tagger inputs are private
  enrichment; narrative/pacing/arc are always 0 in public builds.
  Noted in `FEATURE_NAMES` and a `_schema_note.reserved_features` block
  in weights.json. Kept, not pruned (golden parity).

### Fixed — M3
- **The genre-gate pre-filter silently ate the TMDB graph head**:
  `optimize_candidate_selection` applied the local vote floor BEFORE
  the `via` bypass, so behavioral recommendations under the vote floor
  (often the graph's rank 1-2 "people also liked") were recalled and
  then dropped — engine pairwise on the consensus file jumped 0.72 →
  0.88 once the bypass covers the vote floor too (rating floor stays).
- **`build_user_vector` read a stale embedding-column copy**: the
  module-level from-import meant runtime embedding-space switches
  (tests, smoke scripts, per-model spaces) built user vectors from the
  default column — silently None when that column doesn't exist. Now a
  call-time config read, like queries.py.

### Added — M2 (RFC): exploration budget, feedback loop, NL cold start
- **Exploration budget** (RFC §2) — a deterministic discovery slice on
  every personalized list: `EXPLORE_SHARE` (default 0.12, env
  `CINE_REC_EXPLORE_SHARE`, per-request `explore=` on /similar,
  /for-user, /page; capped 0.5, 0 disables). Eligible picks are NOVEL
  (genre-disjoint from the user's top-3 clusters) AND RELEVANT
  (user-vector affinity ≥ the main list's median) — no RNG anywhere;
  top-3 pinned; picks re-inserted at fixed downstream slots. Without a
  relevance signal it degrades to the plain list — exploration without
  relevance is noise. `/page` also gains a `discover` row: titles
  nearest the user vector OUTSIDE her top clusters (SQL-level genre
  exclusion, ANN-ranked).
- **Outcome feedback loop** (RFC §4) — `POST /feedback {token, outcome,
  tmdb_id}` over the M1 impression tokens (now carrying composite
  id+media_type keys): `click`/`dislike` → `record_feedback` (new
  `click`/`skip` kinds, schema constraint updated), `watch` →
  `record_event` (transactional w_i), `skip` → bounded decay
  `w_item × SKIP_DECAY` (default 0.9, env) — a nudge, never a bury.
  Tokens are HMAC-verified and scoped: only served titles are
  feedable. No trainer, no queue — outcomes flow through the existing
  §D/§J machinery.
- **Natural-language cold start** (RFC §3B) — `GET /by-text?q=…`: a
  virtual seed built from the query text rides the existing
  `seed_info_override` seam. With `CINE_REC_ENCODER="module:function"`
  (bring-your-own encoder), the query embeds and anchors KNN recall +
  the cosine feature (`seed_vectors`); without one, an honest
  popularity-floor fallback ranked by text overlap. No history needed.
- **Shared page context** (M1 latency follow-up) — compose_page fetches
  the user's exclusions + vector ONCE and threads them through every
  row (`find_similar(user_context=…)`): warm /page 160ms → ~75ms on the
  demo stack.
- **Eval beyond-accuracy columns** — coverage@10 and novelty@10 in
  `eval/eval.py` output (pairwise stays column 3, so the CI gate parse
  is unchanged). Baselines on the 10-judgment pool: engine 0.82/0.46 —
  no accuracy regression.
- **Fixed** (found live): the batched semantic-similarity SQL built
  `SELECT id, id, …` unions (`_fact_emb_union` callers prefixed `id,`),
  failing with AmbiguousColumnError on every find_similar and silently
  killing the cosine feature; also `seed_info_override` requests never
  initialized `batch_results` (UnboundLocalError); and a merge indent
  error made `_tilt_scores` return after its first row.

### Added — M1 (RFC): page delivery, session filters, impression tokens
- **`GET /page`** — a page of themed rows in one call
  (`top_picks,because:<id>[:mt],hidden_gems,trending:<genre_id>`): rows
  execute concurrently through the existing pipelines (a `because:` row
  lands in the same find_similar cache entry a direct call would),
  cross-row dedup is first-row-wins, a failing row degrades to an
  omitted row — never a failed page. `hidden_gems` = high-rated
  under-seen titles (rating ≥ 7.0, votes 30–2000 intersected with the
  per-medium floor, ranked rating DESC / votes ASC, movie/tv
  interleaved, scoped to the user's top genre clusters when known).
  `trending:<genre>` = popularity slice above the vote floor.
- **Session/context filters** on `/similar` and `/page`:
  `year_min`/`year_max`, `genres`/`exclude_genres` (genre ids),
  `max_runtime` (minutes; movies only — tv has no runtime column).
  Validated (`queries.normalize_filters` — loud 400s on contradictions
  like a genre both pinned and excluded), applied at the recall
  boundary BEFORE scoring and the limit cut, and hashed into the
  find_similar cache key (`fl=` fingerprint) — a hit can never serve a
  list computed under different constraints.
- **Impression tokens** (`cine_rec_engine/impressions.py`) — every
  served page row carries a stateless HMAC-SHA256 token recording what
  was shown to whom (user, row kind, served ids, exp). Secret:
  `CINE_REC_IMPRESSION_SECRET` (random per-process when unset). M2's
  `/feedback` verifies with the same function.

### Added
- **Controlled item-to-item tilt** — `find_similar(seed, user_id=…)` now
  personalizes the ORDERING, never the pool: after watched/dislike
  filtering and saga advancement, candidates get a boost-only,
  multiplicative affinity term (`score·(1+USER_TILT_ALPHA·max(cos,0))`,
  default α=0.15, env `CINE_REC_USER_TILT_ALPHA`) toward the user's
  vector — ensured on demand in the request's model space. The seed's
  relevance stays primary (a 2× better candidate can never be overtaken;
  negative affinity never buries). Applied post-cache on both the fresh
  and cache-hit paths; results carry `user_affinity` when tilted. The
  shared cache payload remains user-agnostic.
- **RFC for the next evolution** — `docs/rfc-next-evolution.md`: page-of-
  rows delivery (`/page`), deterministic exploration budget, session
  shaping (filter params + natural-language cold start via the virtual-
  seed seam), impression tokens & outcome feedback through the existing
  §D weights (no trainer), and regression hardening. Phased M1–M3.
- **Standalone HTTP serving** — `cine_rec_engine/serve.py`, installed
  via the new `serve` extra: FastAPI `/similar` (bare or `id:media_type`
  seeds, optional `user_id` filtering, `model` space selection),
  `/for-user/{id}` (the personalized row, `include_why`, `model`), and
  `/health` (DB readiness). `Dockerfile` + `.dockerignore` ship a
  single-container service; `CINE_REC_CORS_ORIGINS` opts into CORS;
  every response carries `X-Process-Time-Ms`. Unknown model names are
  400s, mixed seed forms are rejected (movie/tv id collision guard).
- **Per-model user vectors, fully on demand** — `recommend_for_user(vector_space=…)`
  now runs one `REC_MODELS` space end to end: `ensure_user_vector`
  resolves the space's own embedding column, the ANN recall searches
  that column (`emb_column=`), and `find_similar(rec_model=…)` scores
  cosine in the same space. The architecture no longer depends on any
  nightly batch — `nightly_recompute` is optional fleet tooling.
- **Plug-and-play user vectors**: `recommend_for_user` now rebuilds a
  missing or stale user vector inline (`user_vector.ensure_user_vector`)
  before the ANN channel runs — the personalized row works from the
  first request, no nightly cron required. One freshness probe per
  request, at most one rebuild per `USER_VECTOR_MAX_AGE_HOURS` window
  (default 24h, env `CINE_REC_USER_VECTOR_MAX_AGE_HOURS`) per user.
  A registered-model space (`model_spaces.REC_MODELS`, e.g. `e5e`)
  rebuilds from its own embedding column. Every failure mode degrades
  to "no vector" — never an error on the request path.

### Fixed
- **Stored user vectors failed to load (`TypeError: 'Vector' object is
  not iterable`)**: pgvector's asyncpg codec returns `pgvector.Vector`,
  which `list()` cannot iterate. `ensure_user_vector` swallowed the
  error — from a user's SECOND request on, the ANN channel silently
  died AND the `xc=` cache-key component flipped, forcing a full
  pipeline recompute (~1.2 s) instead of a cache hit. Both load paths
  now coerce via `.to_list()`; regression-pinned with real
  `pgvector.Vector` values. `recommend_for_user` warm requests:
  ~1.2 s → ~0.2 s.
- **The KNN recall channels were dead on every schema built from this
  repo (bundled demo included)**: both channels selected the embedding
  column from the `tmdb_media` compatibility view, whose column list is
  fixed at CREATE time — later `ALTER TABLE ... ADD COLUMN` on the fact
  tables never appears in it, so the first KNN query raised
  `UndefinedColumnError` and latched both channels off for the process.
  The channels now query the fact tables directly (per-medium arms,
  ANN-index-served, cross-media merged in SQL).
- **The user-vector ANN query forced a full sort of both fact tables**:
  its `ORDER BY` over the unioned result couldn't use the ANN indexes.
  Each branch now keeps its own `ORDER BY ... LIMIT` (hnsw/ivfflat
  index scan, verified by EXPLAIN) and only the ≤2×limit survivors are
  merged — the query measured ~6× faster at 25k titles.
- **The ANN channel now runs lazily inside `find_similar`** (new
  `extra_factory`/`extra_limit` params): a cache hit skips the ANN
  query entirely (its rows only feed the compute path) while the cache
  key stays stable across requests. The uvec channel's degrade latch
  now disables the key its guard checks instead of one nothing reads.
- **The cosine feature was silently dead alongside the KNN channels**:
  `semantic_overview_similarity` also read embeddings through the
  `tmdb_media` view (empty result on any schema upgraded in place, so
  the plot-similarity feature fell back to nothing for every candidate
  not recalled by KNN). It now reads the fact tables, and multi-seed
  requests use a new `semantic_overview_similarity_batch` — ONE
  cross-join query per blend column instead of one query per seed
  (15–20 queries → 1; ~40 ms total at 25k titles).
- **The two KNN channels issued duplicate queries per seed**: they share
  the same embedding column in every configuration and differ only in
  vote floor, so `find_similar` now runs ONE per seed at the looser
  floor (`generate_knn_candidates(vote_floor=…)`) — the strict-floor
  result was a near-subset of the loose one. ~18 fewer queries per
  personalized request; `ENABLE_KNN_FINETUNED=false` restores the
  strict single-channel form.
- **The per-user filter pass planned catalog-wide scans**: both saga
  queries (seed-saga blocking, watched-saga advancement) now go straight
  at `tmdb_movies` with a new partial index `tmdb_movies_collection_idx`
  (added to `docs/schema.sql`; existing deployments should CREATE INDEX
  CONCURRENTLY the same statement) — the members query measured 67 ms
  through the view, ~15 ms and index-served now.
- **`recommend_for_user` could surface watched/disliked titles outside
  the seed set**: it passed `user_id` to `find_similar` without an
  `exclude` context, and the per-user pass (watched/dislike filtering +
  saga advancement) only runs when `exclude is not None`. It now always
  passes an empty exclude set to arm that pass. Regression-pinned by an
  offline test on the call contract.

## [0.6.0] — 2026-09-28

### Fixed — the public contract (external review round)
- **Composite keys everywhere** (review finding: "TMDB id is not unique
  across media"): `recommend_for_user` now passes `(id, media_type)`
  tuples instead of bare ids; every bridge subquery in the hot
  seed/candidate queries (`genres`, `keywords`, `companies`, `networks`)
  is keyed `(media_id, media_type)` — previously a movie/tv id collision
  could blend genres across media.
- **Cache key completeness**: `limit`, `randomness`, `seed_weights`,
  embedding column, and extra-candidate count are now part of the
  `find_similar` cache key (+ a `v=` format version) — a hit can no
  longer serve a stale list computed under different parameters.
- **Docs match code**: "up to 1000 seeds" → the real `MAX_SEEDS=20`;
  `seed_weights` documented as influence (higher = more), with the
  classic inversion mistake called out.
- README/SECURITY/classifiers aligned to the current version (0.5.x
  support; Python 3.10–3.12 like CI); one catalog number everywhere
  (830).

### Eval honesty
- The "cosine" baseline was character-bigram Jaccard mislabeled. It is
  now **real MiniLM‑384 cosine** on the same vectors the demo ships.
  Result: cosine wins pairwise (0.89 vs 0.82), the engine wins ranking
  (NDCG@10 0.46 vs 0.05) — README states both, with the tradeoff.
- The judgments set is explicitly labeled smoke-scale (10 judgments), a
  regression gate — not a power claim.

### CI
- New `demo-eval` job: real Postgres+pgvector service, seeds the bundled
  catalog, end-to-end engine smoke, then the eval harness as a
  regression gate (pairwise ≥ 0.70). Catches the SQL/enrichment bug
  class (0.5.1 zeroed features, 0.5.3 recall) the offline suite can't.
- `ruff` now covers ingest/, eval/, demo/, benchmarks/ in CI (matches
  the Makefile).

## [0.5.3] — 2026-09-28

### Fixed
- **#1** — cross-media genre recall: a single global `ORDER BY popularity`
  UNION let fresh high-popularity titles bury genre-matching classics
  (Se7en under a Pulp Fiction seed). The channel now orders by
  genre-overlap count, then a vote×rating quality blend, then popularity,
  and keeps a **per-medium budget** — one hot medium can no longer starve
  the other's candidates. Verified: all originally-failing recall pairs
  return; the only remaining "miss" is same-collection saga dedup
  (one slot per story — by design).
- **#2** — persona recommendations in the demo showed WHY labels with
  weight 0.0; they now run the same weighted feature pass as the tab
  seeds (against the persona's top-w_i seed).

## [0.5.1] — 2026-09-28

### Fixed — enriched features were silently zero in ranking
`_entity_profile` (the v0.2.0 hot-path optimization) read keywords,
cast, companies, networks, style and crew ids from the recall row
instead of the enriched data — every enriched feature scored 0 for
every candidate, collapsing ranking onto genre+cosine+rating (and
letting the low-votes flag decide ties; that's how a thin new title
could outrank The Sopranos under a Breaking Bad seed). The parity
tests passed because they exercise the public API, where cand and
cand_data are the same dict. Fixed by mirroring feature_vector's field
ownership exactly; demo re-ranked (Sopranos #1, Better Call Saul via
"same network"), eval NDCG@10 0.36 → 0.49, pairwise unchanged at 0.83.

### Fixed (found by the live smoke)
- pgvector extension is named `vector`, not `pgvector`.
- Aggregation SQL: column ambiguity, LATERAL last-event join, FILTER
  clauses require WHERE, aggregates are illegal inside FILTER.
- rewatch semantics: a re-view of the SAME unit — episodes after the
  first are progress, not rewatch (series scores were inflated ~1.5×).
- `dropped` stays §D.1-pure (a disliked-but-completed movie is completed,
  not dropped).
- pgvector codec registration on every connection that reads vectors.

## [0.2.1] — 2026-09-27

### Fixed (ingest — review findings)
- TV `append_to_response` lost the separator before `external_ids`
  (`…recommendationsexternal_ids,`) — tv `imdb_id` was never fetched. The
  list is now built programmatically (separator bug structurally impossible).
- Bridges MIRROR the payload instead of accumulating: rows removed from
  TMDB (recast actors, dropped keywords/networks/companies) are deleted;
  cast/crew changes upsert (character name, department). Behavioral recs
  prune ranks beyond the fresh page.
- `refresh` is the full daily loop: export diff for ids that crossed the
  popularity threshold after debut (Changes never lists them) → then
  `/changes` pages through the SAME adult + popularity gate as bootstrap.
- `bootstrap` skips ids already in the DB (resumable; `--force` to
  refetch) and ingests concurrently (default 8 queue workers) under the
  token-bucket rate limiter — the serial per-id await made bulk loads
  crawl regardless of the rate budget.

## [0.2.0] — 2026-09-27

### Performance (measured on the 25k-title synthetic bench, PostgreSQL 16)

| scenario | before | after |
|---|---|---|
| cold single-seed `find_similar` (median) | 2,426 ms | **45 ms** (54×) |
| 5-seed `find_similar` | 2,058 ms | **322 ms** (6.4×) |
| warm (cache hit) | 0.4 ms | 0.4 ms |
| scoring loop | 98.2 µs/pair | **26.7 µs/pair** (3.7×) |

- **Scoring loop**: per-entity profiles built once instead of per (candidate,
  seed) pair; lazy imports hoisted; single accumulation pass. Outputs
  within 1 float ULP of the original (golden-vector tests; set-iteration
  order makes float sums hash-seed dependent, so exact bits are not
  portable — sums are now deterministic via sorted iteration).
- **MMR**: incremental max-similarity — n·k pair computations instead of
  k²·n/2, pick order provably identical (30/30 random-trial parity).
- **TMDB sync latency bomb**: 4xx (≠429) responses are non-retryable — an
  absent/invalid API key used to burn ~2s of retry sleeps per cold seed;
  no-key now skips HTTP entirely.
- **KNN channels** latch off after the first missing-column/extension error
  instead of re-running the failing SQL per seed.
- Benchmarks shipped: `benchmarks/bench_scoring.py` (pure-Python hot loop,
  no DB) and `benchmarks/bench_e2e.py` (seeds + drops a synthetic 25k-title
  catalog in any Postgres).

## [0.1.2] — 2026-09-27

### Fixed
- `feature_vector` produced a 27-entry vector against 28 feature names:
  `narrative_match` was computed but never emitted, so from index 22 every
  mood feature was multiplied by its neighbor's weight (`tone_compat` at
  narrative's 1.5 instead of its own 5.0, etc.). The vector now carries
  all 28 features; weight/feature alignment is pinned by tests.

## [0.1.0] — 2026-09-27

First public release: the similar-titles engine, extracted as-is from a
production system that serves it daily.

### Added
- `RecommendationService.find_similar()` — single-seed and multi-seed
  (up to 1,000) similar-title retrieval with per-seed weights,
  movie/series auto-balancing, MMR diversification, and noise control.
- SQL recall channels: genre+popularity, keywords, cast, crew (auteur with
  decay), companies, networks, collections, cached TMDB behavioral
  recommendations, pgvector KNN (optional).
- 22-feature learned scorer; fitted weights published in
  `cine_rec_engine/weights.json` (pairwise logistic regression, 6,650 pairs).
- Per-user filtering: watched/rated exclusions and saga advancement over
  the schema's `user_watches` / `title_ratings` tables (swap in your own
  event tables by editing one SQL constant).
- Graceful degradation for every optional input: embeddings, Redis,
  behavioral cache, cinematic tags — missing pieces disable features,
  never queries.
- In-process TTL cache fallback when Redis is absent.
- `docs/schema.sql` (full expected schema), `docs/data.md` (building a
  daily-refreshed local TMDB mirror), offline test suite (40 tests).
